## Trigger: the owner's compile failure

```
e: FrameViewerScreen.kt:215:17 'fun ColumnScope.AnimatedVisibility(...)' cannot be called
in this context with an implicit receiver. Use an explicit receiver if necessary.
```

`AnimatedVisibility` has two families of overloads: the plain one and `ColumnScope`/`RowScope`/`BoxScope` receiver versions that add `expand/shrink` toward the parent axis. Inside a `Column`, the unqualified call resolves to the **ColumnScope overload**, so it only compiles where the immediate implicit receiver is that `ColumnScope`. Two call sites violated this:

1. **Frame resolving badge (~line 215):** sits inside the stage `Box`, which is nested inside the root `Column`. `@LayoutScopeMarker` hides the outer `ColumnScope`, so the implicit call was unresolvable.
2. **Error overlay (~line 267):** sits in the root `Box` with no `ColumnScope` in scope at all — this would have been the *next* compiler error after fixing the first.

### Fixes (FrameViewerScreen.kt)

- Badge: explicit receiver — `this@Column.AnimatedVisibility(visible = state.isFrameLoading, modifier = Modifier.align(Alignment.TopEnd).padding(12.dp)) { FrameResolvingBadge() }`.
- Error overlay: plain `AnimatedVisibility` driven by a remembered `MutableTransitionState` (target state set from `state.errorMessage != null`), with `enter = fadeIn() + expandVertically()` / `exit = fadeOut() + shrinkVertically()`. The transition-state form also fixes the old behavior where the content lambda read `state.errorMessage?.let { ErrorCard(...) }` while `visible` was already false, which could pop content out mid-exit animation.
- Hoisted `thumbnails.sortedBy { it.frameIndex }` into `remember(thumbnails)` so it no longer re-sorts on every recomposition of the timeline row.

## Bug-hunt findings and fixes

Grouped by severity. "Fixed" means source changed + statically reviewed + `git diff --check` clean — **not** compiled.

### P0 — crash / build blockers

1. **Home empty-state crash (HomeAndImportScreens.kt).** When `recentProjects.isEmpty()`, the root `Column` got `verticalScroll` *and* contained `Spacer(Modifier.weight(1f))`. A weighted child in the scroll axis receives unbounded constraints → `IllegalStateException` at first measure. This fires on **first launch** (no projects yet), i.e., the very first screen a new user sees. Restructured: bounded root `Column`; scrollable inner `Column(modifier = Modifier.weight(1f))` for the empty state; `AnalysisPrinciples()` pinned outside the scroll region so it no longer scrolls away.
2. **`OverlayEffect(listOf(overlay))` (ExportManager.kt).** Media3 `OverlayEffect` takes a Guava `ImmutableList<TextureOverlay>`, not a Kotlin `List`. Changed to `OverlayEffect(ImmutableList.of(overlay))`. This is a probable compile error that was hiding behind the `AnimatedVisibility` failure.

### P1 — correctness

3. **Carry-forward parity broken (AnnotationSession / ExportManager / SwingFrameViewModel).** Preview (`AnnotationSession.carriedFor`) and still export drew carried "ghost" vectors on every frame — including frames that had their own exact annotations — but video export only drew carried shapes `if (exact.isEmpty())`. Same session, different burned-in output. Fix: extracted the single rule into `annotation/CarryForward.kt` (`carriedAnnotationsFor(map, frameIndex, radius = 3)`; nearest frame wins, past checked before future at each distance) and made all three surfaces (preview session, still export, video export) call it. Removed the private `carriedFor`/`carriedAnnotations(...)`/`CARRY_RADIUS` copies. Regression tests in `CarryForwardTest.kt` (5 tests: past-over-future precedence, future fallback, empty-frame skip, inclusive radius boundary, empty map).
4. **Playback cadence drift (MediaSessionController.kt).** The loop recomputed `displayAtMs = now + frameDurationMs` each iteration, so decode/wait time was silently added to every frame's deadline and playback ran slow vs. the clock. Now the schedule is wall-clock anchored: `displayAtMs = maxOf(displayAtMs, now) + frameDurationMs; delay(displayAtMs - now)`, with `coerceAtLeast(1L)`.
5. **Still/video export strokes ~3× thinner than preview (AnnotationBitmapRenderer.kt).** Preview draws with `strokeWidthDp.dp.toPx()` (density-based), but export scaled by `minDim/1080` — at 1080p output that is scale 1.0 (clamped ≥0.7), while a typical phone preview is ~3×. Burned-in arrows/lines/text looked hairline compared to what the user composed. Export scale is now `minDim/360` (≈ density-equivalent: 360dp ≈ 1080px at 3× density), clamped 1–8. Angle label text (`28f*scale → 13f*scale`) and offset (`12f*scale → 9f*scale`) re-tuned to match the preview's dp proportions at 1080p.
6. **Accidental-tap ghost angle (AnnotationCanvas.kt).** A tap (no drag) with the angle tool completed a degenerate zero-length angle draft, leaving a stray "0°" label on the frame. The completion branch now discards the draft when there is no `pendingAngle` and no drag.

### P2 — polish / hygiene

7. **`CompactAction` touch target (AnnotationControls.kt).** Content measured under 48dp tall despite the audit's touch-target claim. `Surface` now has `defaultMinSize(minWidth = 48.dp, minHeight = 48.dp)`.
8. **Duplicate snapshot work (SwingFrameViewModel.kt).** `exportCurrentFrame` called `annotationSession.snapshot(frameIndex, carryForwardEnabled)` twice with identical args. Captured once, reused.
9. **Preview scaling on the decode thread (Media3FrameDecoder.kt).** `FrameExtractor` pins decode calls to the application thread; `decodePreviewFrame` also did the CPU-bound bitmap downscale there, serializing it against decode during rapid scrubbing. Decode still happens where required; the `scaledForPreview` step now runs on `Dispatchers.Default`.
10. **Version skew (app/build.gradle.kts).** `SOURCE_REVISION.txt` said `0.5.1-hardening-r2` but `versionName` was `0.5.1-hardening`. Aligned to `0.5.1-hardening-r2`.
11. **Dead dependency (app/build.gradle.kts).** Removed `androidx.media3:media3-ui-compose` — repo-wide grep showed zero usages.
